## [CURRENT_TASK]

Подготовить комплект тестовой документации на фичу **Authorization** для `fullstack-next`.

1. **`README.md`** — назначение, границы (in/out of scope), окружения и как их поднять, инструменты
   (браузер + DevTools: Network/Application, `curl`), критерии входа/выхода, распределение
   приоритетов.
2. **`test-plan.md`** — стратегия (functional, security, negative, regression), что входит/не входит,
   риски и допущения, зависимости (Keycloak, backend, nginx), критерии начала и завершения
   тестирования, метод фиксации дефектов.
3. **`test-cases.md`** — таблица кейсов `TC-AUTH-xxx` со столбцами: ID, название, тип, приоритет,
   предусловия, шаги, ожидаемый результат, трассировка. Обязательно покрыть:
   - **Вход (позитив):** вход `admin-user` и `user-user`; возврат на `user-kit.next.local`.
   - **Вход (негатив):** неверный пароль, отмена на странице провайдера, `?authError=1`.
   - **Сессия:** сохранение после перезагрузки (`/api/v1/me`), истечение/сброс → `401` → экран входа,
     refresh до истечения (проверить, что сессия живёт).
   - **Выход:** `POST /logout` без 403, очистка cookie, `redirectUrl`, повторный вход требует учётку.
   - **Роли:** `admin-user` видит admin-раздел; `user-user` — не видит и получает отказ от сервера.
   - **Dev-режим:** `dev-login` с CSRF; роль применяется; доступно только при `DEV_AUTH_ENABLED=true`.
   - **Режим `none`:** вход недоступен, понятное поведение; `login` → ошибка/`oidc_disabled`.
   - **Disabled-аккаунт:** `disabled-user` не получает доступ.
   - **Кросс-домен:** сессия `user-kit.local` не даёт доступа на `user-kit.next.local` и наоборот.
4. **`security-checklist.md`** — проверки:
   - токенов нет в `localStorage`/`sessionStorage`/DOM и в бандле `.next/static`;
   - небезопасные методы без `X-XSRF-TOKEN` отклоняются; с токеном — проходят;
   - фронтенд не ставит заголовок `Authorization`; нет прямых вызовов token endpoint Keycloak;
   - cookie HttpOnly/`SameSite=Lax`/`Secure` по конфигу;
   - прямой запрос к admin-ресурсу под `user` → отказ; анонимный запрос к приватному маршруту → `401`;
   - logout ревокует сессию (старые cookie больше не работают).
5. **`test-data.md`** — таблица учёток/ролей/состояний и требуемые значения переменных окружения для
   каждого режима (`OIDC_*`, `DEV_AUTH_ENABLED`).
6. **`traceability.md`** — матрица: каждый `FR-AUTH`/AC → минимум один `TC-AUTH`; пометить
   непокрытые требования как пробелы.
